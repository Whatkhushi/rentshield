# RentShield: rental handover & deposit protection

[![CI](https://github.com/Whatkhushi/rentshield/actions/workflows/ci.yml/badge.svg)](https://github.com/Whatkhushi/rentshield/actions/workflows/ci.yml)

**Tenants and landlords document a rental's condition together, keep a record neither side can quietly change, compare it at move-out, and settle the security deposit item by item with evidence.**

## The problem

In Indian cities a security deposit of **2 to 10 months' rent** is common. At move-out, disputes usually come down to one sentence: *"it was already like that."* Neither side has an agreed record of the flat's condition on day one. Scattered WhatsApp photos prove little: the other party never agreed to them, and nobody can tell whether they changed. Deductions often arrive as a single number, with no breakdown and no evidence.

**RentShield** is a simple, independent tool for the two people involved. It is not a property marketplace, a broker CRM or an all-in-one landlord suite.

## Features

| | Feature | What it does |
|---|---|---|
| 1 | **Joint inspection** | Room-by-room checklists (generated from room names), condition + notes + photos per item, meter readings. The other party **approves or disputes each item**; disputed items get revised and re-reviewed until both agree. Then the record **locks**. |
| 2 | **Tamper-evident evidence** | Every file is **SHA-256 fingerprinted on the server while it streams in**. Anyone on the tenancy can re-verify a file at any time. Every action goes into a **hash-chained, append-only audit log**. |
| 3 | **Move-out comparison** | Move-out reuses the move-in items 1:1. The camera shows the **move-in photo as a ghost overlay** to line up the same shot. Compare with a **before/after slider**, side by side, or an in-browser **SSIM heatmap** of regions that look different. |
| 4 | **Evidence-backed settlement** | The landlord proposes itemised deductions, each with a reason, linked to the inspection item (move-in vs move-out photos shown together) and optional invoices. The tenant **accepts or disputes each one**; the landlord revises or withdraws. Refund calculated live; **both must confirm**. |
| 5 | **Two-party access** | Either side creates the tenancy and shares a **single-use, expiring invite link**. The other side joins in the browser, no app install. Every record is authorised **per tenancy**. |
| 6 | **PDF report** | Generated by a **background job**: both inspections with photos, agreed/disputed items, deductions and responses, final settlement, file fingerprints re-verified at generation, and the audit log with chain status. |

### What it deliberately doesn't claim
- A fingerprint proves a file **hasn't changed since upload**. It doesn't prove when or where a photo was taken.
- A highlighted difference is a **hint**, not proof of who caused damage. It's only reliable on aligned photos, which is why the ghost overlay exists.
- The PDF is an organised record both parties acknowledged, **not a guaranteed legal document**.

## Architecture

```
 React SPA ──REST /api/v1──► Express API ──Prisma──► PostgreSQL
                               │   │                    ▲
                               │   └── pg-boss queue ───┘  (jobs stored in Postgres)
                               │          └── worker: PDF generation
                               ▼
                       Storage interface ── local disk (uploads)
```

A **modular monolith**: one deployable app organised by module (`auth`, `leases`, `inspections`, `evidence`, `settlements`, `reports`). In production one Docker image serves both the API and the built React app from one origin.

## Engineering highlights (interview notes)

- **Optimistic locking.** Every inspection item and deduction has a `version`. Updates run `UPDATE … WHERE id = ? AND version = ?`; if someone else changed it first, 0 rows match and the API returns **409 STALE_VERSION** instead of silently overwriting.
- **Hash-chained audit log.** `hash = SHA256(prevHash + canonical JSON of the event)`. Changing any old entry breaks every hash after it, and `/leases/:id/audit` finds the first broken link.
- **No forks in the chain.** Appending locks the lease row (`SELECT … FOR UPDATE`) inside the transaction, so concurrent writers line up. A test fires 6 uploads at once and checks the chain is still valid.
- **Append-only enforced by the database.** A Postgres trigger rejects `UPDATE`/`DELETE` on `AuditEvent`, so even an application bug can't rewrite history (tested).
- **Hash while streaming.** A custom Multer storage engine pipes each upload through a SHA-256 transform straight to storage: no temp files, and the hash is of exactly the bytes received. Authorisation runs **before** any bytes are accepted.
- **Money invariants in transactions.** Deductions are created under a row lock on the settlement, and the total can never exceed the deposit (**409 EXCEEDS_DEPOSIT**). Any change clears both parties' confirmations.
- **No lost finalization.** The last approval locks the inspection row, so two simultaneous approvals can't both miss that they finished the review.
- **Race-safe invitations.** Conditional updates (`WHERE acceptedAt IS NULL`, `WHERE landlordId IS NULL`) mean two people opening the same link can't both join (tested).
- **Access control per tenancy.** Every lease-scoped route checks membership; outsiders get **404** (not 403), so IDs can't be probed. Invite tokens and refresh tokens are stored **only as hashes**.
- **Background jobs without Redis.** pg-boss stores jobs in Postgres, survives restarts and retries failures. The API returns **202 Accepted** and the UI polls.

## Running locally

### With Docker
```bash
docker compose up --build
```
Open http://localhost:8080.

### Without Docker
Needs Node 22+ and PostgreSQL.
```bash
cd server
cp .env.example .env        # set DATABASE_URL / TEST_DATABASE_URL
npm install
npx prisma migrate deploy
npm run db:seed             # demo data
npm run dev                 # API on http://localhost:4100

cd ../web
npm install
npm run dev                 # app on http://localhost:5174
```
> Windows: if PowerShell says "running scripts is disabled", use `npm.cmd` instead of `npm`.

### Tests
```bash
cd server
DATABASE_URL=<test db> npx prisma migrate deploy
npm test
```

The 16 integration tests cover: the full dispute → revise → agree cycle, optimistic locking, a file changed on disk being detected, the DB refusing to edit audit history, concurrent chain writes, invite races, deposit limits, settlement maths and PDF generation.
